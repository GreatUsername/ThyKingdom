# tools

Скрипты поддержки Кодекса и проекта. Лежат в репозитории, чтобы работать на любой машине, а не только там, где были написаны.

Нужен Python 3.9 или новее. Внешних зависимостей нет.

Пути скрипты определяют от собственного расположения, поэтому запускать их можно из любого каталога и на любой машине. Каталоги по умолчанию: Кодекс — `Notes/Thy Kingdom/Codex`, сценарии проекта — `Project/scenarios`.

## `pad_tables.py` — выравнивание таблиц

Приводит markdown-таблицы к тому виду, который делает встроенный форматтер Obsidian: ячейки дополняются пробелами по ширине колонки, строка-разделитель состоит из нужного числа дефисов, переводы строк сохраняются.

Зачем: если таблицу правит скрипт, а не Obsidian, она перестаёт быть выровненной и в истории появляется шум из пробелов. Скрипт этот шум убирает.

```
python tools/pad_tables.py            # весь каталог Кодекса
python tools/pad_tables.py --check    # только показать, что изменилось бы
```

## `update_register_summary.py` — сводка реестра

Пересчитывает таблицу «Сводка» в `03 Mechanics register.md`, разбирая строки самого реестра. Сводка не может разойтись с содержимым, потому что считается из него. Если в строках появится статус, которого нет в сводке, скрипт предупредит.

Зачем: сводка, набранная руками, ошибается. В этом реестре она ошибалась дважды, после чего и был написан скрипт.

```
python tools/update_register_summary.py
python tools/update_register_summary.py --check
```

## `reflow_notes.py` — одна строка на абзац

Сводит перенесённые строки так, чтобы каждый абзац занимал одну строку — это правило 7 в `00 Codex`. Строки, которые должны остаться отдельными, не трогаются: frontmatter, блоки кода, таблицы, заголовки, горизонтальные линии, цитаты, элементы списков и поля решений вроде `**Решение:** —`.

Преобразование затрагивает только пробелы и выполняется целиком или никак: если нормализованный текст хотя бы одного файла изменился, скрипт не записывает ничего и сообщает, где расхождение.

```
python tools/reflow_notes.py            # весь каталог Кодекса
python tools/reflow_notes.py --check    # только проверка
python tools/reflow_notes.py <файл>     # один файл
```

## `check_notes.py` — структурные проверки

Ищет то, чего не видно глазами:

- сдвоенные заголовки вида `## Термины хода## Термины хода`;
- повтор первого столбца в таблицах словаря;
- повтор номеров механик в реестре и пропуски в нумерации;
- повтор номеров решений и расхождение между строкой статуса и разделом.

Зачем: сдвоенный заголовок и повторное определение термина уже случались, причём оба раза виноват был скрипт правки, а не рука, и оба раза ошибка находилась через несколько правок после появления. Проверка стоит секунду.

```
python tools/check_notes.py
```

## `run_scenarios.py` — прогон сценариев проекта

Прогоняет все сценарии из `Project/scenarios` через прогонщик и сверяет полученный хеш с эталонным из секции `[expect]`. Это единственный скрипт здесь, который относится не к Кодексу, а к проекту.

Зачем: эталонный хеш проверяет только тот, кто не забыл запустить прогонщик руками. Скрипт делает это за него, печатает таблицу и возвращает ненулевой код, если хоть один сценарий разошёлся, поэтому его можно вписать в сборочный шаг.

```
python tools/run_scenarios.py
python tools/run_scenarios.py --runner Project/build-tools/runner/runner.exe
python tools/run_scenarios.py --scenarios Project/scenarios
```

Прогонщик ищется в `Project/build/runner/runner.exe`; если его там нет, скрипт печатает команду сборки и выходит с кодом 2. Коды возврата: 0 — все сошлись, 1 — есть расхождения или ошибки, 2 — нет прогонщика или каталога со сценариями.

Сценарий с `hash = 0` считается **провалом**, а не пропуском: он ничего не сверяет, но выглядит как зелёная проверка. Эталон меняют осознанно — сначала объясняют, что изменилось в мире, потом вписывают новый хеш.

## Порядок при ручной правке

1. `reflow_notes.py` — свести абзацы в одну строку.
2. `update_register_summary.py` — пересчитать сводку, если правился реестр.
3. `pad_tables.py` — выровнять таблицы.
4. `check_notes.py` — убедиться, что структура цела.

Порядок важен: пересчёт сводки меняет значения ячеек и оставляет выравнивание устаревшим, поэтому `pad_tables.py` идёт последним. Впрочем, `update_register_summary.py` теперь выравнивает сводку сам, так что запуск в обратном порядке тоже ничего не испортит.

Все три шага безопасны для содержимого: `reflow_notes.py` проверяет это сам, а `pad_tables.py` меняет только пробелы внутри таблиц.
